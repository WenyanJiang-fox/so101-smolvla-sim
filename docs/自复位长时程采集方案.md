# SO-101 自复位长时程采集方案

2026-09-19 定稿。目标是让机械臂无人值守地连续跑：一边执行抓放任务，一边把过程录成训练数据。

## 一、一轮是怎么走的

1. 俯视相机 + CV 定位：找出**目标颜色**方块的实际位置
2. 用**实测位置**（不是命令位置）算 IK，去抓
3. 成功判定：夹爪闭合角 + 回到 home 后俯视复查目标位是否已空
4. 抓起，移动到随机落点，放下
5. 用 CV 测实际落点，和命令落点的差**记下来补进下一轮的放置命令**（闭环标定）
6. 回 home，落一条日志：轮次、实测位置、结果、耗时、异常
7. 下一轮

## 二、三层分工

| 层 | 负责 | 手段 |
|---|---|---|
| 底层 | 精确复现 | 关节空间轨迹 / IK 位姿控制 |
| 中层 | 粗定位、成功判定 | 俯视相机 + 颜色分割 |
| 顶层 | 决策、异常处理 | LLM 生成任务 / 脚本调度 |

本轮只做基础任务：**抓起来、移动、放下**。采集由 LLM + 专家脚本完成，VLA 先不参与采集环节。

## 三、防场景漂移

先厘清一件事：**只要落点是独立重采的，就不存在漂移**。漂移只从两处来——落点由「从物体当前位置往外推」决定，或抓失败时夹爪把物体推走了一点。所以对策分两类。

**主方案（做完这两条框架就稳了）**

1. **落点复用采集时的 spawn 参数。** 用 `pick_env.py:232-266` 那套：`config.spawn_min_radius`、`spawn_max_radius`、`spawn_angle_half_range_deg`，以及包里的 `sample_separated_positions`（带 `min_object_separation`）。放置点用同一组参数、同一个函数采，分布**按构造**与训练集一致；每轮独立重采，无累积。
2. **抓取目标用 CV 实测值。** 这一步同时解掉两件事：抓准了就不会把物体推走，累积来源断掉；顺带消掉「命令落点 vs 实际落点」的系统偏差。

**工程细节（必做）**

3. **采样过滤**，四个条件缺一不可：IK 有解（用现成的 `inverse_kinematics` 试解，无解重采）、落在桌面内、在俯视相机视野内、不撞机械臂基座。

**兜底与监控（可后补）**

4. **实测位置越界 → 触发一次归位**：把方块推回区域内，或重新随机放一次。
5. **每 N 轮软复位**：例如每 100 轮把三个方块依次放回标准位置一次，防住没想到的累积效应。
6. **每轮记录 CV 实测的物体位置**，定期比对当前分布和采集时分布的偏离，超阈值报警或触发重置。这是唯一能让人**发现**问题还在不在的手段。

## 四、成功判定

两条判据各管一件事，不能互相替代：

- **夹爪闭合角**：判「爪子里有没有东西」。抓空时爪子会合到行程尽头，抓住方块时停在半途，两个闭合角差得很开，用舵机读回的关节角就能分辨。判不了「东西对不对」。
- **俯视相机看颜色**：判「是不是目标颜色」。必须在**抓之前**看目标位置坐的是不是目标色——抓起之后爪子一包住方块，腕部相机就看不见了。
- **回到 home 后俯视复查目标位**：兜底，覆盖「抓起来中途掉了」。

## 五、还没解决的缺陷

按严重度排。这些都不在方案里，是已知的空白。

1. **进程崩了不能续跑。** 这是「跑一夜」最常见的死法。现在的采集脚本是一条进程跑到底、最后才 `finalize()`；相机句柄泄漏、OpenCV 取帧失败、任何未捕获异常都会让整条链停住。需要：每轮包 try、异常记日志后继续、崩溃后能从第 N 轮重启。
2. **成功率会随时间单调下降。** 两个来源——舵机连续运行发热（力矩下降、零点漂移），夹爪指腹摩擦材料磨损（为防滑落把爪面摩擦调到了 4，磨掉之后会变滑）。后果不是崩溃，是**前后半夜的数据质量不一样**，混在一起训练会引入一个和时间相关的伪标签。需要读舵机温度寄存器、定期休息、把轮次时间戳记进数据，事后按时间段分开检查成功率。
3. **光照变化。** HSV 阈值分割对光照敏感，跑一夜遇到开关灯或天亮，阈值就失效，CV 定位跟着失效，整条链断掉。要么固定照明，要么改用对光照不敏感的方法（ArUco 码）。
4. **颜色调度没定。** 链条里抓哪个颜色由谁决定？如果由 CV「看到哪个抓哪个」，采出来的颜色分布不受控，可能和位置相关——这直接关系到最初要解决的问题（模型不读语言）。链条必须**显式调度**目标颜色，并且和落点独立。
5. **数据落盘时机。** `LeRobotDataset.create` 在进程结束时才 `finalize()`，跑 8 小时中途断掉，前面 episode 可能不完整。要么定期 finalize，要么分段开新数据集。
6. **方块掉地上 = 链条卡死。** 落点过滤的是桌面内，但抓失败可能把方块推出桌沿；掉下去之后 CV 找不到它，后续所有轮次都失败。需要检测「物体消失」并触发介入或专门的捡回动作。
7. **没有对照组。** 要证明这套采集方式有用，需要基线（同等人力的脚本采集或遥操作采集）。否则跑出几万条也说不清好在哪。
8. **失败条要不要录、录多少。** 链条会自然产生失败（抓空、掉件）。录下来就是 DAgger 数据，但之前判定 retry 数据只作辅助，混入比例还没定。这个策略得在采集时就有，不能事后补。

## 六、待定参数

- 落点区域的半径与角度范围（对齐采集时的 spawn 参数）
- 每 N 轮软复位的 N
- 失败条是否入库、入库比例
- 单次连续运行的时长上限（受舵机发热限制）
